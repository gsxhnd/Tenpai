# AI 训练设计

> 状态：论文事实 + 项目设计草案
>
> 本文档以论文 `Suphx: Mastering Mahjong with Deep Reinforcement Learning` (`arXiv:2003.13590`) 为主要参考。
> 当前仓库尚未提供完整训练代码，所以下文分为两类内容：
> - `论文事实`：可直接从论文中确认的方法与结论
> - `项目设计`：为了在本仓库中落地复现而提出的实现方案

## 1. 目标与边界

### 1.1 训练目标

Tenpai 的训练目标不是构建一个抽象的“万能麻将模型”，而是尽量贴近 Suphx 的做法，逐步得到可用于四人立直麻将决策的策略集合。

第一阶段优先实现以下能力：
- 从天凤高质量牌谱中提取监督学习样本
- 分动作训练多个策略模型，而不是把所有决策塞进一个单模型
- 建立 round 级别的全局奖励预测能力
- 为后续自博弈强化学习和运行时策略适配打基础

### 1.2 不做什么

以下内容不应被表述为当前训练主线：
- 不将 `Transformer` 作为论文对应的主干网络
- 不将 `PPO` 写成论文默认强化学习算法
- 不将 `MCTS` 写成论文关键贡献
- 不把雀魂 GUI 自动化验证作为训练闭环的一部分

## 2. 论文方法的正确映射

### 2.1 Suphx 解决的问题

四人日麻训练难点主要有：
- 多玩家博弈，且是非零和环境
- 不完全信息，无法直接观测对手手牌
- 单局收益和最终排名之间存在长时序依赖
- 决策目标不是单纯和牌，而是提升整场排名表现

### 2.2 论文中的核心方法

根据论文，Suphx 的关键点不是“更深的单模型”，而是以下组合：

1. `五个动作模型`
   - 弃牌（discard）
   - 立直（riichi）
   - 吃（chi）
   - 碰（pon）
   - 杠（kan）

2. `规则型和牌决策`
   - 和牌判断由规则逻辑直接处理
   - 不是把和牌动作完全交给神经网络学习

3. `卷积网络主干`
   - 输入是结构化牌局特征张量
   - 论文主干是 CNN，而非 Transformer

4. `global reward prediction`
   - 通过预测整场收益缓解长期信用分配问题
   - 重点不是手工 reward shaping

5. `oracle guiding`
   - 使用更强信息条件下的教师信号辅助训练
   - 目的是提升策略质量与收敛效率

6. `parametric Monte-Carlo policy adaptation (pMCPA)`
   - 在推理时根据比赛上下文调节策略风格
   - 例如末局领先时更防守，落后时更追求高打点翻盘

### 2.3 本项目必须统一的术语

后续文档统一使用以下术语：
- `global reward prediction`：全局奖励预测
- `oracle guiding`：Oracle 引导
- `pMCPA`：参数化蒙特卡洛策略适配
- `record rank`：记录段位
- `stable rank`：稳定段位

以下说法不建议继续使用：
- “全局奖励塑形”
- “论文主线是 MCTS”
- “单一 policy/value 网络覆盖全部动作”

## 3. 训练对象拆分

### 3.1 为什么要拆成多个模型

论文中的动作空间天然分裂为多类条件决策：
- 自摸后是否立直、是否杠、打哪张牌
- 他家弃牌后是否吃、碰、杠

这些动作的触发条件、样本分布、类别空间都不同。如果强行合并成一个大网络，会让：
- 标签分布更稀疏
- 训练样本极不平衡
- 不同任务之间互相干扰

因此 Tenpai 的训练设计应先按动作拆分。

### 3.2 建议的训练单元

| 模型 | 输入上下文 | 输出 | 训练来源 |
| --- | --- | --- | --- |
| `discard_model` | 自己摸牌后的完整状态 | 34 类弃牌分布 | 监督学习 + RL |
| `riichi_model` | 可立直状态 | 是/否 | 监督学习 |
| `chi_model` | 上家出牌且可吃 | 吃/不吃或候选吃法 | 监督学习 |
| `pon_model` | 任意他家出牌且可碰 | 碰/不碰 | 监督学习 |
| `kan_model` | 暗杠/加杠/大明杠机会 | 杠/不杠 | 监督学习 |
| `reward_predictor` | 多轮对局序列 | 整场收益或排名相关信号 | 序列监督 |

其中：
- `discard_model` 是 RL 的主要承载对象
- 其他动作模型可以先以监督学习为主，后续再视效果决定是否纳入 RL

## 4. 数据需求

### 4.1 监督学习数据

每条牌谱至少要被转换为以下样本：
- 弃牌样本：在每次合法弃牌时记录状态和专家动作
- 立直样本：在每次可立直时记录是否立直
- 吃样本：在每次可吃时记录最终选择
- 碰样本：在每次可碰时记录最终选择
- 杠样本：在每次可杠时记录最终选择

最低要求不是“保存原始 JSON 就够了”，而是要把原始牌谱转成可训练样本表。

### 4.2 全局奖励预测数据

为了支持 `global reward prediction`，还需要构造 round 级别序列数据，例如：
- 东 1 到南 4 的局进展序列
- 每局结束后的分数变化
- 庄家轮转、本场数、立直棒数
- 当前名次与最终名次之间的关系

这类数据与单步动作标签不同，不能混在普通分类样本里处理。

### 4.3 数据切分建议

建议至少拆成三类集合：
- `train`：用于监督学习和 reward predictor 训练
- `validation`：用于模型选择和早停
- `evaluation`：固定离线评估集，避免边训边调污染结果

如果后续引入在线评测，应与离线集合严格分离。

## 5. 输入表示

### 5.1 论文对应的输入思路

论文图示表明，输入不仅包括手牌，还包括：
- 手牌计数编码
- 副露状态
- 弃牌序列
- 宝牌与宝牌指示牌
- 场风、自风
- 本场数、立直棒数
- 各家点数与顺位上下文

### 5.2 项目设计建议

为保持和论文一致，建议先采用“多通道离散特征张量”而不是文本序列表示。

推荐分块：
- `hand channels`：34 种牌的持有张数编码
- `meld channels`：副露内容与来源信息
- `discard channels`：各家弃牌及顺序特征
- `dora channels`：宝牌指示与可见宝牌信息
- `table context`：局数、巡目、点数、庄家、本场、立直状态
- `look-ahead features`：向听、有效牌、安牌候选等可解释特征

这里的 `look-ahead features` 应明确标注为项目中的规则辅助特征，不要误写成纯端到端方案。

## 6. 网络结构建议

### 6.1 第一阶段采用 CNN 主干

为了与论文保持一致，第一版训练设计建议：
- 采用卷积或残差卷积主干
- 为不同动作模型共享编码规范，但保留独立输出头或独立模型
- 保持结构简单，先追求可训练与可解释，再考虑更复杂主干

一个可行的基线结构：

```text
输入特征张量
    -> 卷积层 / 残差块
    -> 全连接层
    -> 动作头
```

对应输出：
- 弃牌模型输出 34 类概率
- 立直/碰/杠模型输出二分类概率
- 吃模型输出二分类或有限候选动作分布

### 6.2 暂不承诺的结构

以下方向可以保留为未来实验，但不应写成当前默认方案：
- Transformer 主干
- 统一 policy/value 双头大模型
- 跨框架导出 TensorFlow SavedModel

## 7. 训练流程

### 7.1 阶段一：监督学习

目标：从高质量人类牌谱学习基础策略。

建议流程：
1. 从牌谱中抽取五类动作样本
2. 为每类样本建立单独的数据集与指标
3. 训练五个动作模型的初始版本
4. 保存离线评估结果，作为后续 RL 基线

建议监控指标：
- `discard top-1 accuracy`
- `riichi precision / recall`
- `chi/pon/kan accuracy`
- 按局况切片的准确率，如是否听牌、是否有人立直、南场末局等

### 7.2 阶段二：全局奖励预测

目标：让模型具备“当前决策如何影响整场排名”的辅助判断能力。

建议流程：
1. 将牌谱转换为对局序列样本
2. 训练一个独立的 `reward_predictor`
3. 在训练和评估中记录它对最终收益信号的拟合效果

这个阶段的重点是长期信用分配，不是继续添加手工奖励项。

### 7.3 阶段三：自博弈强化学习

目标：在监督学习策略之上继续优化真实对局表现。

项目设计建议：
- 先只对 `discard_model` 引入 RL
- 其他模型保持 SL 版本作为稳定决策模块
- 采用分布式自博弈生成样本
- 建立固定基线对手与历史版本池，避免策略震荡

文档层面当前只应承诺这些原则，不应提前写死具体算法名、超参数和收敛时间。

### 7.4 阶段四：推理时策略适配

目标：根据牌局上下文动态调整策略，而不是固定用一套参数打所有局面。

论文对应方法是 `pMCPA`，它强调：
- 在领先时更关注守住排名
- 在落后时更偏向高收益翻盘路线
- 决策目标与当前局面、点差、剩余局数有关

Tenpai 后续若要实现该能力，建议单独记录：
- 输入哪些局况特征
- 适配的是模型参数、采样温度还是候选策略权重
- 如何离线验证策略适配的收益

## 8. Oracle 引导

### 8.1 论文中的角色

`oracle guiding` 不是“规则引擎过滤非法动作”这么简单。
它更接近一种训练辅助信号：在拥有更强信息的条件下，为策略学习提供更稳定的目标或引导。

### 8.2 项目中的可落地方向

在本仓库中，可以把 Oracle 设计为实验性训练辅助模块，例如：
- 使用完整牌山或对手隐藏信息构造理想化标签
- 计算更高置信度的危险度或收益上界
- 在训练时作为辅助损失，而不是在线推理输入

如果暂时做不到，应明确写为“计划中”，不要伪装成已完成能力。

## 9. 评估设计

### 9.1 离线评估

离线阶段至少需要覆盖：
- 各动作模型的分类指标
- 关键局况切片表现
- reward predictor 的误差指标
- 对历史牌谱的回放式决策评估

### 9.2 在线评估

为了和论文主线一致，在线评估说明应优先围绕天凤而不是雀魂：
- 使用与训练日志来源一致的平台更容易闭环验证
- 更适合讨论 `record rank` 与 `stable rank`
- 也更接近论文报告方式

如果未来继续探索雀魂验证，应在其他文档中标注为实验扩展。

## 11. 后续落地顺序

建议按以下顺序推进：

1. 明确训练数据合同
   - 原始牌谱如何转换为五类动作样本和序列样本
2. 先实现监督学习基线
   - 至少先跑通 `discard_model`
3. 补齐 reward predictor
   - 验证全局收益信号是否可学习
4. 再引入自博弈 RL
   - 优先验证离线收益和稳定性
5. 最后实验 `oracle guiding` 与 `pMCPA`
   - 作为增强项逐步加入
