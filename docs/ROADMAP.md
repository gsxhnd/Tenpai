# ROADMAP

Tenpai 的路线图以“先把论文主线做实，再逐步扩展”为原则。

## Phase 0: 文档与边界

目标：让项目范围、术语和主线顺序稳定下来。

- [x] 重写架构文档，区分现状、目标和缺口
- [x] 重写数据文档，明确样本合同
- [x] 重写训练文档，对齐 `Suphx` 方法
- [x] 重写开发文档，移除虚构实现
- [x] 降级雀魂方向为实验性扩展
- [x] 新增术语表与文档导航

## Phase 1: 数据流水线基线

目标：从原始牌谱稳定生成可训练样本。

- [ ] 定义原始牌谱存储格式与版本号
- [ ] 实现结构化事件流解析
- [ ] 实现合法动作集重建
- [ ] 导出 `discard` 样本
- [ ] 导出 `riichi` 样本
- [ ] 导出 `chi` / `pon` / `kan` 样本
- [ ] 导出 `reward predictor` 序列样本
- [ ] 实现整场级别的 `train / validation / evaluation` 切分
- [ ] 补充数据质量统计与回归检查

交付结果：
- 稳定的数据合同
- 可复用的样本导出流程
- 初始质量报告

## Phase 2: 监督学习基线

目标：先跑通最小可行训练闭环。

- [ ] 实现统一特征编码
- [ ] 实现 `discard_model` 数据读取与训练循环
- [ ] 建立最小离线评估指标
- [ ] 记录基线结果与误差案例
- [ ] 再扩展到 `riichi` / `chi` / `pon` / `kan` 模型

交付结果：
- 第一个可训练、可评估的基线模型
- 统一输入特征和样本接口

## Phase 3: 全局奖励预测

目标：补上长期目标建模能力。

- [ ] 定义序列样本输入格式
- [ ] 实现 `reward_predictor` 基线
- [ ] 评估长期收益相关信号是否可学习
- [ ] 将 reward predictor 纳入训练分析链路

交付结果：
- 可独立评估的长期奖励预测模块

## Phase 4: 自博弈强化学习

目标：在监督学习基线上提升真实对局表现。

- [ ] 先针对 `discard_model` 设计 RL 实验
- [ ] 构建固定基线对手与历史版本池
- [ ] 建立自博弈样本生成机制
- [ ] 明确离线与在线评估协议
- [ ] 记录策略改进与退化案例

交付结果：
- 第一版可复现实验的自博弈训练流程

## Phase 5: 论文增强项

目标：逐步补齐 `Suphx` 中最关键但更复杂的部分。

- [ ] 设计 `oracle guiding` 标签与辅助损失
- [ ] 设计 `pMCPA` 的上下文输入与调节策略
- [ ] 验证领先 / 落后局况下的策略适配效果

交付结果：
- 更贴近论文主线的增强能力

## Phase 6: 实验扩展

目标：在不扰动主线的前提下探索额外方向。

- [ ] 设计独立的在线评估文档
- [ ] 评估是否需要外部平台接入
- [ ] 如果继续探索，再单独推进雀魂只读实验
- [ ] 在确认合规与工程成本后，再评估自动化实验

交付结果：
- 与主线解耦的实验路线

## 当前优先级

接下来最重要的不是再扩文档，而是开始实现：

1. 牌谱解析与事件流
2. 动作合法性重建
3. `discard` 样本导出
4. `discard_model` 监督学习基线
5. 最小离线评估协议
